# B04 - Incorrect evidence should be marked as Discarded

## Symptoms
- When the walkie lady says an evidence is wrong, it is just unselected instead of marked as Discarded (red).

## Investigation
- "Discarded" corresponds to `evidences_missing` in `GhostGuess`.
- Need to find the walkie lady feedback logic and update how it modifies `GhostGuess`.

## Findings
- Incorrect evidence in `repellent_feedback.rs` is already being toggled with `discard: true`.
- The `apply_journal_evidence_toggle` in `unghost-plugin/src/systems/journal.rs` correctly adds the evidence to `evidences_missing` when `discard: true` is received.
- However, the user reports it's just being "unselected" instead of "discarded".
- Looking at `apply_journal_evidence_toggle`, if `msg.discard` is true, it toggles: if already missing, remove it.
- In the walkie trigger, it sends `discard: true`. If it was NOT missing, it will now be inserted into `evidences_missing`.
- Wait, if it was ALREADY in `evidences_found`, it removes it from `evidences_found` and adds to `evidences_missing`. This seems correct.
- Maybe the problem is that it only toggles, so if it's already discarded it might un-discard it? But the trigger should only fire once.
- Actually, the user says "it should be marked as Discarded (red)". In the UI, red usually means `evidences_missing`.
- I'll verify the UI coloring logic for `evidences_missing`.
