# B03 - Journal selections not reset

## Symptoms

- Evidence and ghost selections in the journal persist between missions.

## Investigation

- `GhostGuess` resource holds this state.
- Need to clear `GhostGuess` on mission start and end on the server.

## Findings

- `GhostGuess` is both a resource and a component on `MissionGoalEntity`.
- `MissionGoalEntity` is spawned on `OnEnter(SimulationState::Spawning)` and despawned on
  `OnEnter(SimulationState::TearingDown)`.
- The server/host's local `GhostGuess` resource might not be reset, and since `sync_ghost_guess_to_mission_goal` only
  syncs when changed, it might carry over old data if not explicitly reset.
- Action: Reset `GhostGuess` resource in both `setup_goal_entity` and `cleanup_ghost_entities` on the server.
