### `unui-core`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Shared UI widgets and styling primitives

#### Dependencies

No internal game crate dependencies. External: `bevy`, `bevy_asset_loader`.

#### Contents

Modules: `assets`, `components/`, `events/`, `resources`.

**`assets.rs`** — `UiAssets` (AssetCollection/Resource): declares `Handle<Image>` and `Handle<Font>` fields for every
shared UI texture (title, backgrounds, scroll widgets, badges, vignette) and an exhaustive set of font families
(Londrina Solid, Syne, Overlock, Chakra Petch, Titillium Web, Victor Mono, Kode Mono). Loaded via `bevy_asset_loader`
during `AppState::EngineBoot`.

**`components/game_ui.rs`** — In-game HUD markers: `EvidenceUI`, `GameUI`, `ElementObjectUI` (3-variant enum),
`DamageBackground { exp: f32 }`, `HeldObjectUI`, `RightSideGearUI`, `WalkieTextUIRoot`, `WalkieText`.

**`components/hint_ui.rs`** — `HintBoxUIRoot`, `HintBoxText`: markers for the on-screen tutorial hint overlay.

**`components/summary_ui.rs`** — `SCamera`, `SummaryUI`, `SummaryUIType` (18-variant enum covering all post-mission
report fields: GhostList, TimeTaken, DifficultyName, FinalScore, GradeAchieved, NetChange, FinalBankTotal, etc.).

**`events/hint.rs`** — `OnScreenHintEvent { hint_text: String }` (`Message`-derived): triggers the in-game hint overlay;
typically fired by the walkie-talkie system.

**`resources.rs`** — `MouseVisibility { is_visible: bool }` (Resource): tracks cursor visibility for HUD interactions.

#### Tier Assessment

The crate has no internal game dependencies and only touches `bevy` and `bevy_asset_loader` — correct for a foundational
UI-data crate at T4. However, it is used as a **shared component carrier** by a large number of lower-tier crates,
creating a broad upward dependency problem.

The root causes of the violation pattern:

1. **HUD markers** (`WalkieTextUIRoot`, `WalkieText`, `DamageBackground`, `EvidenceUI`, etc.) are placed in T4. Domain
   plugins that spawn or update in-game entities with HUD sub-elements cannot attach these markers without importing T4.
2. **`UiAssets`** (font handles) is placed in T4. Any plugin that needs to spawn text for its own UI reads `UiAssets`,
   forcing a T4 import.
3. **`OnScreenHintEvent`** is plain string data. Walkie-related domain code fires it to display hints — another forced
   upward dep.

**Reverse consumers (violations):**

_T1 domain crates (each is a T1→T4 violation):_

- `unlocomotion-plugin` (T1·1b)
- `unvitals-plugin` (T1·1c)
- `unlight-plugin` (T1·1a)
- `unplayer-plugin` (T1·1b)
- `untruck-plugin` (T1·1c)
- `unwalkie-plugin` (T1·1c)

_T2 application crates (each is a T2→T4 violation):_

- `uninput-plugin` (T2)

_T3 infrastructure crates (each is a T3→T4 violation):_

- `unmaphub-plugin` (T3·3a)
- `unhub-plugin` (T3·3c)

_Legitimate T4 consumers:_ `unui-plugin`, `unmenu-core`, `unmainmenu-plugin`, `uncampaign-plugin`, `unlobby-plugin`,
`unmenusettings-plugin`, `unmanual-plugin`, `unsummary-plugin`, `unclassic-mode-ui-plugin`

#### Violations

**🔴 T1→T4 (×6): Six T1 domain plugins import `unui-core`**

All six need either HUD marker components or `UiAssets` font handles. Placing these in T4 forces every domain plugin
that touches the HUD or walkie system to carry a presentation-layer dependency.

**🔴 T2→T4 (×1): `uninput-plugin` imports `unui-core`**

The input binding plugin imports `unui-core`, likely for `UiAssets` (font handles for in-game key rebinding display or
similar).

**🔴 T3→T4 (×2): `unmaphub-plugin` and `unhub-plugin` import `unui-core`**

Infrastructure adapters must not depend on presentation.

#### Recommendation

Partition `unui-core` into two layers:

- **New T0/T1 crate** (e.g., `ungame-ui-types` or `unhud-core`): pure ECS marker components (`WalkieTextUIRoot`,
  `WalkieText`, `DamageBackground`, `EvidenceUI`, `HintBoxUIRoot`, etc.) and plain events (`OnScreenHintEvent`). No
  `bevy_asset_loader`, no `Handle<*>`. Removes T1/T2/T3 violations.
- **T4 remainder** (`unui-core`): `UiAssets` (asset handles), `SummaryUIType`, `MouseVisibility`, and anything that must
  couple to the asset pipeline. Only T4 plugincrates import this.

### `unui-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Shared UI base plugin

#### Dependencies

Internal: `unui-core` (T4·4c), `untypes-core` (T0), `unfoundation-core` (T0), `unrender-std` (T4·4a), `unreplicon-core`
(T2). External: `bevy`, `bevy_asset_loader`.

All internal deps are T0, T2, or T4 peers — correct for T4.

#### Contents

Three substantive files: `plugin.rs`, `hide_mouse.rs`, `pause_ui.rs`.

**`plugin.rs`** — `UnhaunterUiPlugin`: registers `UiAssets` asset collection (loaded during `AppState::EngineBoot`),
registers `OnScreenHintEvent` as a message, and delegates to `hide_mouse::app_setup` and `pause_ui::app_setup`.

**`hide_mouse.rs`** — `system_hide_mouse`: tracks `CursorMoved` events; hides the system cursor when the player is in
`AppState::InGame / GameState::Running` for more than 3 seconds without mouse movement. Updates `MouseVisibility`
resource. `show_mouse_cursor_on_exit` restores cursor visibility on `OnExit(AppState::InGame)`.

**`pause_ui.rs`** — `setup_ui` / `cleanup` / `keyboard`: spawns a minimal pause overlay using `UIPanelMaterial` (from
`unrender-std`) when entering `GameState::Pause`. The overlay shows "Pause / Press ESC to resume or Q to quit" or a
"Host has left" message (read from `unreplicon_core::resources::HostGone`). Keyboard system handles ESC (resume) and Q
(quit to lobby or mission select depending on `LobbyPresenceRole`). `keyboard_pause` handles ESC→Pause transition from
`GameState::Running`.

#### Tier Assessment

Correctly placed at T4·4c. Imports T4·4a (`UIPanelMaterial`) and T2 (`HostGone`, `LobbyPresenceRole`) — both downward or
same-level. No violations.

#### Violations

None.

### `unmenu-core`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Pause / pop-up menu

#### Dependencies

Internal: `unui-core` (T4·4c), `unfoundation-core` (T0), `untypes-core` (T0), `unprofile-core` (T3·3b). External:
`bevy`.

All downward deps for a T4 crate. `unprofile-core` (T3) is used to render the player status bar.

#### Contents

Modules: `components`, `events`, `templates`, `scrollbar`, `mission_select`.

**`components.rs`** — Marker and logic components for menus: `MenuItemInteractive { identifier, selected }`,
`MenuRoot { selected_item }`, `MenuMouseTracker { mouse_moved }`, `PrincipalMenuText`, `MenuItemDisabled`,
`MenuBackground`, `MenuContentArea`, `MenuStrip`, `MenuHelpText`, `MenuUI`.

**`events.rs`** — Four message types: `KeyboardNavigate(usize)` (arrow-key navigation),
`MenuItemClicked { state: AppState, pos: usize }`, `MenuItemSelected(usize)`, `MenuEscapeEvent`.

**`templates.rs`** — A library of UI construction helpers (not systems): `create_background`, `create_logo`,
`create_menu_strip`, `create_menu_item`, `create_menu_item_disabled`, `create_help_text`, `create_standard_menu_layout`
(complete menu layout in one call), `create_breadcrumb_navigation`, `create_informational_content_area`,
`create_selectable_content_area`, `create_content_item`, `create_player_status_bar` (reads `PlayerProfileData` to show
Level / XP / Bank). All accept `&mut ChildSpawnerCommands` or `&mut Commands` and return `EntityCommands`. They
reference `UiAssets` for fonts and `unfoundation_core::colors` for theme colors.

**`scrollbar.rs`** — `build_scrollbar_ui`: spawns the scrollbar sub-tree (up arrow button, track container, thumb, down
arrow button) into a parent. Uses `UiAssets` for scroll arrow/thumb images. Marker components:
`ScrollableListContainer`, `ScrollbarContainer`, `ScrollbarTrack`, `ScrollbarThumb`, `ScrollbarUpArrow`,
`ScrollbarDownArrow`.

**`mission_select.rs`** — `MissionSelectMode` enum (Campaign / Custom), `CurrentMissionSelectMode` (Resource).

#### Tier Assessment

Correctly placed at T4·4c. All dependencies are T0, T3 (persistence, read-only), or T4 peer. The `templates.rs` file is
the largest individual item — a factory for reusable menu layouts. Placing UI factory code in a `-core` crate is unusual
(normally only data belongs there), but here it serves as a shared library used by every screen plugin, so the choice is
pragmatic. No violations.

#### Violations

None.

### `unmenu-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Menu interaction systems plugin

#### Dependencies

Internal: `unmenu-core` (T4·4c), `unfoundation-core` (T0), `untypes-core` (T0), `untags-core` (T0). External: `bevy`.

All downward deps for a T4 plugin. Notably no `unui-core` dep — all UI types come through `unmenu-core`.

#### Contents

Systems in `systems.rs`; scrollbar systems in `scrollbar.rs`; `plugin.rs` registers both.

**`systems.rs`** — Four systems:

- `menu_mouse_movement_system`: tracks `MouseMotion` events, sets `MenuMouseTracker.mouse_moved = true` on first
  movement (prevents spurious hover-selection on menu open).
- `menu_interaction_system`: reads `Interaction` changes on `MenuItemInteractive` entities; dispatches
  `MenuItemSelected` (hover, after mouse moved) and `MenuItemClicked` (press).
- `menu_keyboard_system`: arrow up/down → `MenuItemSelected` + `KeyboardNavigate`; Enter → `MenuItemClicked`; Escape →
  `MenuEscapeEvent`.
- `update_menu_item_visuals`: reads `MenuRoot.selected_item`, updates `BackgroundColor` and `TextColor` of all menu item
  entities to reflect selected vs. hovered vs. idle states. Falls back from `PrincipalMenuText` marker to first child if
  no marked principal text exists.

Also spawns/despawns a `Camera2d` (`MCamera`) on `OnEnter/OnExit(AppState::MainMenu)` and despawns all `MenuUI` entities
on exit.

**`scrollbar.rs`** — Four systems: `update_scroll_position` (mouse wheel → `ScrollPosition`), `update_scrollbar` (syncs
thumb position and arrow button alpha to current scroll percentage), `handle_scrollbar_interactions` (click up/down
arrows, drag thumb), `ensure_selected_item_visible` (keyboard navigation → auto-scrolls so selected item stays in view
with 80px margin).

#### Tier Assessment

Correctly placed at T4·4c. All systems operate on UI-layer components. No upward violations.

#### Violations

None.

### `unmainmenu-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Title screen plugin

#### Dependencies

Internal: `unfoundation-core` (T0), `unui-core` (T4·4c), `untypes-core` (T0), `unmenu-core` (T4·4c), `unprofile-core`
(T3·3b). External: `bevy`, `bevy-persistent`.

All downward deps for a T4 plugin.

#### Contents

Single logic file `mainmenu.rs` with `plugin.rs` registering it.

**`mainmenu.rs`** — `MenuID` enum (Campaign, CustomMission, MultiplayerLobby, Hub, Manual, Settings, Disconnect, Quit)

### `uncampaign-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Mission selection screen

#### Dependencies

Internal: `undifficulty-core` (T1·1c), `unfoundation-core` (T0), `unsummary-core` (T4·4c), `unui-core` (T4·4c),
`untmxmap-core` (T3·3a), `unmapload-core` (T3·3a), `untypes-core` (T0), `unmenu-core` (T4·4c), `unprofile-core` (T3·3b).
External: `bevy`, `bevy-persistent`.

All internal deps are T0, T1, T3, or T4 peers — correct for T4.

#### Contents

Two logic files: `unified_mission_selection.rs`, `badge_utils.rs`; `plugin.rs` wires the single `app_setup` call.

**`badge_utils.rs`** — `BadgeUtils`: a stateless utility struct with one associated function `create_badge`. Reads
`unsummary_core::grade::Grade` (T4·4c) and `UiAssets` (T4·4c) to spawn a `TextureAtlas`-backed `ImageNode` badge icon.
Used by the mission list to show per-map completion grades.

**`unified_mission_selection.rs`** — The entire mission-selection screen, unified across both Campaign and Custom modes.
Registers two resources (`UIMissionMapping`, `InitialScrollTarget`) and five systems (`setup_ui`, `cleanup_ui`,
`handle_selection_input`, `update_mission_selection`, `trigger_initial_scroll_if_needed`). Key responsibilities:

- Filters and sorts `Maps` from `untmxmap-core` by `CurrentMissionSelectMode` (campaign vs. custom) and `player_level`.
- Partitions missions into available/locked lists; initially scrolls to the most advanced affordable mission in campaign
  mode.
- Mission detail pane shows description + preview image; updated reactively via `MenuItemSelected`.
- On confirmation: validates the player's `bank >= required_deposit`, updates `CurrentDifficulty`, persists
  `PlayerProfileData`, writes `LoadLevelEvent`, and transitions to `AppState::MissionLoading`.
- Locally spawns / despawns its own `Camera2d` and root `MissionSelectUI` node.

#### Tier Assessment

Correctly placed at T4·4c. All dependencies are T0, T1, T3, or T4 — no upward leaks. The crate reads T1 domain data
(`CurrentDifficulty`, `DifficultySettings`) and T3 persistence data (`PlayerProfileData`, `Maps`) purely for display and
navigation — consistent with a presentation layer consuming lower-tier outputs.

#### Violations

None.

### `unlobby-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Multiplayer lobby screen

#### Dependencies

Internal: `unfoundation-core` (T0), `unui-core` (T4·4c), `untypes-core` (T0), `untmxmap-core` (T3·3a), `unmenu-core`
(T4·4c), `unreplicon-core` (T2), `unmapload-core` (T3·3a), `undifficulty-core` (T1·1c), `unprofile-core` (T3·3b),
`unrender-std` (T4·4a). External: `bevy`, `bevy-persistent`, `enum-iterator`.

All internal deps are T0–T4 — correct for T4.

#### Contents

`plugin.rs` + `systems/` (four modules: `setup`, `lobby_main`, `map_select`, `difficulty_select`).

**`plugin.rs`** — `UnhaunterLobbyPlugin`: initialises the `LobbyScreen` sub-state (from `untypes-core`), then delegates
all system registration to `systems::setup::app_setup`.

**`systems/setup.rs`** — `app_setup`: registers per-`LobbyScreen` sub-state pairs of `OnEnter/OnExit` setup and `Update`
systems for `LobbyScreen::{Main, MapSelection, DifficultySelection}`. `enter_lobby` spawns a camera and transitions to
`LobbyScreen::Main`; `exit_lobby` despawns camera, all `MenuUI` entities, and resets to `LobbyScreen::None`.

**`systems/lobby_main.rs`** — The main lobby UI: player list (colored boxes + nicknames with "You" highlight), map
preview, difficulty display, deployment status pulse, and a role-aware sidebar menu (`SelectMap`, `SelectDifficulty`,
`StartMission`, `AbortMission`, `ExitLobby`). Only the room owner sees `SelectMap/SelectDifficulty`. `StartMission`
toggles to "Join Mission" when a `SelectedMission` entity exists (server-confirmed mission). `AlphaModulator` (from
`unrender-std`) drives a text-alpha pulse on the deployment status text. Reads `LobbyInfo`, `LocalPlayer`,
`RoomIdentification`, and replicon message types from `unreplicon-core`.

**`systems/map_select.rs`** — Sub-screen for choosing a map within the lobby. Builds a scrollable list from `Maps`;
sends `RequestSelectMap` to `unreplicon-core` on selection; returns to `LobbyScreen::Main` on escape.

**`systems/difficulty_select.rs`** — Sub-screen for choosing difficulty within the lobby. Lists all `Difficulty`
variants (via `enum-iterator`); sends `RequestSelectDifficulty` on selection.

#### Tier Assessment

Correctly placed at T4·4c. Imports from T2 (`unreplicon-core` — networking/lobby data) and T4·4a (`unrender-std` —
`AlphaModulator`) are appropriate downward/peer-level deps. No violations.

#### Violations

None.

### `unmenusettings-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Settings UI

#### Dependencies

Internal: `unui-core` (T4·4c), `unfoundation-core` (T0), `untypes-core` (T0), `unsettings-core` (T3·3b), `unmenu-core`
(T4·4c). External: `bevy`, `bevy_platform`, `bevy-persistent`, `strum`.

All internal deps are T0, T3, or T4 peers — correct for T4.

#### Contents

Modules: `plugin.rs`, `components.rs`, `menu_ui.rs`, `menus.rs`, `systems.rs`.

Correctly placed at T4·4c. Reads T3·3b persistence structs (`AudioSettings`, `VideoSettings`, `GameplaySettings`)

### `unsummary-core`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Post-mission report data

#### Dependencies

Internal: `unghost-core` (T1·1b), `undifficulty-core` (T1·1c). External: `bevy`, `serde`.

Both internal deps are T1 — correct downward direction for a T4 crate.

#### Contents

Two modules: `grade.rs`, `summary.rs`.

**`grade.rs`** — `Grade` enum (A, B, C, D, F, NA). Methods:

- `multiplier() -> f64`: score weight per grade (A=5.0 … NA=0.0).
- `badge_index() -> usize`: sprite atlas index 0–5 for a badge image — a UI rendering concern embedded directly in a
  data type.
- `color() -> bevy::Color`: per-grade colour for UI labels — another UI concern baked into the enum.
- `description() -> &str`, `from_score(score, a, b, c, d thresholds) -> Grade`.
- Implements `Ord` (by multiplier), `Display`, `From<&str>`, `From<String>`.
- Derives `Serialize`, `Deserialize`, `Reflect`, `Default` (NA).

**`summary.rs`** — `SummaryData` (Resource + Component, serialisable/reflectable): holds all mission-outcome fields:
`time_taken_secs`, `ghost_types: Vec<GhostType>`, `difficulty: CurrentDifficulty`, `grade_achieved: Grade`,
`money_earned`, `average_sanity`, `player_count`, `alive_count`, `full_score`, `map_path: String`, `mission_successful`,
and the full financial breakdown (`required_deposit`, `mission_reward_base`, `deposit_returned_to_bank`, etc.).
`MissionEvaluator` trait: `calculate_base_score(&SummaryData) -> i64`, `evaluate_grade(i64) -> Grade`.
`ActiveMissionEvaluator(pub Box<dyn MissionEvaluator>)` Resource. `calculate_score()` applies the difficulty multiplier.

#### Tier Assessment

`SummaryData` and `Grade` are mission-outcome domain types used broadly across T1, T2, and T3 crates. Their placement at
T4·4c is incorrect: the workspace Cargo.toml groups them with UI crates, but their actual consumers span every tier
below T4. The only T4-appropriate content in the crate is `Grade::badge_index()` and `Grade::color()` — methods that
reference sprite atlas indices and `bevy::Color` for on-screen display.

Reverse consumer grep against all `Cargo.toml` files confirms 8 lower-tier crates import `unsummary-core`:

- `unplayer-plugin` (T1·1b): tracks per-player sanity/alive state into `SummaryData`.
- `unghost-plugin` (T1·1b): reads `SummaryData` for mission-success detection.
- `unvitals-plugin` (T1·1c): writes vitals stats into `SummaryData`.
- `ungearitems-plugin` (T1·1c): records gear-usage metrics into `SummaryData`.
- `unmission-plugin` (T2): lifecycle events interact with `SummaryData`.
- `unreplicon-plugin` (T2): replicates `SummaryData` fields across the network.
- `unclassic-mode-orchestrator-plugin` (T2): populates `SummaryData` at mission end.
- `unprofile-core` (T3·3b): the player save-file struct references `SummaryData`-derived values.

Legitimate T4 consumers: `uncampaign-plugin` (T4·4c), `unsummary-plugin` (T4·4c).

#### Violations

**🔴 T1→T4 (×4):** `unplayer-plugin`, `unghost-plugin`, `unvitals-plugin`, `ungearitems-plugin` all import
`unsummary-core` (T4·4c). Domain plugins at T1 must not cross the presentation boundary.

**🔴 T2→T4 (×3):** `unmission-plugin`, `unreplicon-plugin`, `unclassic-mode-orchestrator-plugin` all import
`unsummary-core` (T4·4c). Application-layer orchestrators must not depend on presentation-layer crates.

**🔴 T3→T4 (×1):** `unprofile-core` (T3·3b) imports `unsummary-core` (T4·4c). Infrastructure persistence crates must not
depend on presentation-layer types.

#### Recommendation

Split the crate:

- **New T1·1c crate** (e.g., `unmission-outcome-core`): pure domain data — `SummaryData`, `MissionEvaluator` trait,
  `ActiveMissionEvaluator`, and `Grade` without `badge_index()`/`color()`. All T1/T2/T3 consumers migrate here.
- **T4 remainder** (`unsummary-core`): only the UI-specific `Grade` extensions (`badge_index()`, `color()`) and any
  T4-only rendering helpers. Consumed only by `unsummary-plugin` and `uncampaign-plugin`.

### `unsummary-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Post-mission summary screen plugin

#### Dependencies

Internal: `undifficulty-core` (T1·1c), `untmxmap-core` (T3·3a), `unfoundation-core` (T0), `unboard-core` (T1·1a),
`untypes-core` (T0), `unsummary-core` (T4·4c), `unui-core` (T4·4c), `unprofile-core` (T3·3b), `unplayer-core` (T1·1b),
`unghost-core` (T1·1b). External: `bevy`, `bevy-persistent`.

All internal deps are T0, T1, T3, or T4 peers — correct for T4.

#### Contents

Two files: `plugin.rs`, `summary.rs`.

**`plugin.rs`** — Registers two plugins:

- `UnhaunterSummaryCorePlugin`: initialises `SummaryData` resource; `update_time` runs on `FixedUpdate` in
  `AppState::InGame`; `calculate_rewards_and_grades` runs `OnEnter(SimulationState::TearingDown)` gated to
  `AuthorityRole`.
- `UnhaunterSummaryPlugin`: full summary screen for `AppState::Summary`. `OnEnter` chain: `setup` → `store_mission_id` →
  `calculate_rewards_and_grades` (non-authority clients) → `setup_ui` → `insert_afk_timer` → `finalize_profile_update`.
  `OnExit`: cleanup. `Update`: `keyboard`, `afk_timeout`, `update_ui`, `update_score`.

**`summary.rs`** — All system implementations:

- `setup`: spawns `Camera2d` tagged with `SCamera`.
- `setup_ui`: builds a 3-column CSS-grid layout using `UiAssets` fonts and `SummaryUIType` marker components from
  `unui-core`. Displays grade badge (sprite atlas), score counter, full financial breakdown, and reward/bank totals.
- `update_ui`: reactive text population for all 18 `SummaryUIType` variants reading `SummaryData`.
- `update_score`: animated counter that increments toward `animated_final_score`.
- `calculate_rewards_and_grades`: derives `Grade` from `Maps` thresholds, fills `money_earned` and `grade_multiplier` on
  `SummaryData`.
- `finalize_profile_update`: writes mission stats, bank balance, XP, and map records into `PlayerProfileData` and
  persists via `bevy-persistent`.
- `store_mission_id`: reads `BoardTopology` to fill `SummaryData.map_path`.
- `update_time`: tracks elapsed time, average sanity, player alive count, and detects all-dead → transitions to
  `AppState::Summary`. Contains a code-level TODO: _"Consider moving mission stat-tracking to `unmission-plugin`"_,
  acknowledging that lifecycle detection sits uncomfortably in a presentation-layer plugin.
- `keyboard` / `afk_timeout`: ESC/Enter navigate to lobby or mission select; 30-second auto-advance.

#### Tier Assessment

Correctly placed at T4·4c. All dependency directions are downward. `update_time`'s dual role (HUD stat accumulation +
mission-lifecycle transition trigger) is a known design tension noted in the source code; it does not create a tier
violation but is an architectural smell: mission end detection belongs in the domain or application layer, not in the
summary screen plugin.

#### Violations

None.

### `unclassic-mode-render-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** Game-mode-specific visual overrides

#### Dependencies

Internal: `unbehavior` (T3·3a), `unboard-core` (T1·1a), `unghost-core` (T1·1b), `unnavigation-core` (T1·1a),
`unplayer-core` (T1·1b), `unmapload-core` (T3·3a), `unpicking-core` (T4·4a), `unsoundfield-core` (T1·1a), `unrender-std`
(T4·4a), `unreplicon-core` (T2), `unsettings-core` (T3·3b), `unspatial-core` (T0), `untags-core` (T0), `untmxmap-core`
(T3·3a), `untypes-core` (T0). External: `bevy`, `bevy-persistent`, `bevy_replicon`.

All internal deps span T0–T4 — correct downward direction for a T4 plugin.

#### Contents

Modules: `plugin.rs`, `camera.rs`, `hydration.rs`, `cleanup.rs`. (`systems/` directory is empty.)

**`plugin.rs`** — `ClassicModeRenderPlugin`: delegates to `hydration::app_setup`, `camera::app_setup`,
`cleanup::app_setup`, and registers `sync_ghost_visuals` on `Update` in `AppState::InGame`.

**`camera.rs`** — Systems registered on `OnEnter(AppState::InGame)` and `Update`:

- `setup`: despawns any existing `GCameraArena` camera and spawns a fresh `Camera2d` with 224-pixel fixed-height
  orthographic projection, `GCameraArena`, `Direction`, and `CustomSpritePickingCamera` markers.
- `camera_follow_system`: smooth player-follow camera with read-ahead bias based on player movement direction; optional
  keyboard panning (WASD) and zoom (Numpad +/−) controlled by `GameplaySettings.camera_controls`.
- `debug_tile_transforms`: 5-second periodic diagnostic — counts active/hidden map tile sprites and logs
  mean/std-dev/min/max of their alpha values alongside pending hydration stage counts.

**`hydration.rs`** — Three reactive hydration systems, each gated on `LocalPlayerRole` presence (headless guard —
dedicated servers skip all of these):

- `hydrate_players_system` (trigger: `Added<PlayerSprite>` without `PlayerHydrated`): attaches visual mesh
  (`CustomMaterial1`), animation timer, spatial audio listener (local player only), input mapping, `MainPlayer`,
  `VisibilityData`, `FocusRing` child entity, and gameplay components (`Movable`, `WaypointQueue`, `LerpPosition`,
  etc.). FIXME noted: `FocusRing` child is NOT replicated; possible orphan on client-side despawn.
- `hydrate_ghosts_system` (trigger: `Added<GhostSprite>` without `GhostHydrated`): attaches visual mesh, `Ethereal`,
  `Emissive`, `SpectralClarity`, `AlphaModulator`, `EctoplasmVisuals`, `LightSensitive`, `UltravioletSensitive`,
  `ThermalEmitter`, `FluidEmitter`, `SoundFieldSource`, `LerpPosition`, `FocusRing` child.
- `hydrate_breach_system` (trigger: `Added<GhostBreach>` without `BreachHydrated`): visual mesh with breach-curve
  ectoplasm animation, thermal/fluid/sound emitters, `FocusRing` child.
- `sync_ghost_visuals` (Update): syncs `SpectralClarity` (UV/RL/alpha channels) from `GhostBehaviorDynamics`.

**`cleanup.rs`** — `cleanup_game` on `OnExit(AppState::InGame)`: resets `BoardTopology`, `BoardCollisionField`,
`BoardEntityField`; transitions `SimulationState` to `Unloaded`; despawns `GCameraArena` (excluding replicated entities)
and all `GameSprite` entities.

#### Tier Assessment

Correctly placed at T4·4c. The crate is a pure presentation-layer adapter: it consumes replicated domain entities and
attaches the local visual/audio/input components they need to be rendered and interacted with on the client. All
dependencies are downward. No violations.

Note: the FIXME comment in `hydration.rs` about orphaned `FocusRing` children on `despawn_recursive` is a correctness
risk in multiplayer but is not a tier violation.

#### Violations

None.

### `unclassic-mode-ui-plugin`

**Audit date:** 2026-03-20 **Assigned tier:** T4·4c (UI) **Declared role:** HUD and in-game UI

#### Dependencies

Internal: `unbehavior` (T3·3a), `unfoundation-core` (T0), `ungear-core` (T1·1c), `unplayer-core` (T1·1b), `unrender-std`
(T4·4a), `unui-core` (T4·4c), `unsettings-core` (T3·3b), `untypes-core` (T0). External: `bevy`, `bevy-persistent`.

All internal deps are T0, T1, T3, or T4 peers — correct for T4.

#### Contents

Modules: `plugin.rs`, `game_ui.rs`, `gear_ui.rs`, `looking_gear.rs`, `resources/hint_ui_state.rs`,
`systems/hint_ui_system.rs`.

**`plugin.rs`** — `ClassicModeUiPlugin`: delegates to `hint_ui_system::app_setup`, `game_ui::app_setup`,
`looking_gear::app_setup`.

**`game_ui.rs`** — Main HUD layout (spawned `OnEnter(AppState::InGame)`, cleaned up on exit, paused/resumed with
`GameState::Running`):

- Walkie text overlay (`WalkieTextUIRoot` / `WalkieText`): centred at top, hidden until text arrives.
- Two `DamageBackground` panels (full-screen black flash + vignette image) that animate on damage.
- Key-legend sidebar: lists movement / interaction bindings from `GameplaySettings`.
- Bottom HUD bar: left gear slot (`gear_ui::setup_ui_gear_inv_left`), centre evidence panel (`EvidenceUI`), right gear
  slot + stats (`gear_ui::setup_ui_gear_inv_right` inside `RightSideGearUI`).
- `toggle_held_object_ui` system (Update, `GameState::Running`): reads `PlayerGear.held_item` and updates
  `ElementObjectUI::Name` / `Description` / `Grab` text nodes to reflect the currently held interactable object.

**`gear_ui.rs`** — Two helper functions (not systems) for spawning gear inventory widgets:

- `setup_ui_gear_inv_left`: left-hand slot — `ImageNode` backed by `GearAssets` sprite atlas (`Inventory::new_left()`),
  TAB-key label, `InventoryStats::left()` text.
- `setup_ui_gear_inv_right`: right-hand slot — next-item preview (`InventoryNext`), main right slot
  (`Inventory::new_right()`), `InventoryStats::right()` text.

**`looking_gear.rs`** — Initialises `LookingGear` resource on startup; `system_update_looking_gear` reads
`PlayerInputMapping` from `MainPlayer` and updates `LookingGear.toggle` (on key press) and `LookingGear.held` (while key
held) in `AppState::InGame`.

**`resources/hint_ui_state.rs`** — `HintUiState` (Resource): animation state machine with `HintAnimationPhase` (Idle /
AnimatingIn / Visible / AnimatingOut), timers, and configurable durations (slide-in 300ms, visible 16s, slide-out
300ms).

**`systems/hint_ui_system.rs`** — Registers:

- `setup_hint_ui_system` (`OnEnter(InGame)`): spawns an absolutely-positioned `HintBoxUIRoot` panel off-screen at the
  left edge.
- `hint_ui_event_and_animation_system` (Update, `InGame`): reads `OnScreenHintEvent` events; drives the `HintUiState`
  state machine with ease-out (slide-in) and ease-in (slide-out) curves; mutates `Node.left` to animate the panel.
  Auto-advances to `AnimatingOut` after the visible-duration timer expires.
- `cleanup_hint_ui_system` (`OnExit(InGame)`): despawns `HintBoxUIRoot`.

#### Tier Assessment

Correctly placed at T4·4c. All dependencies are downward. The crate is a clean presentation-layer HUD: it reads domain
state (`PlayerGear`, `Behavior`, `PlayerInputMapping`, `LookingGear`) and routes UI events (`OnScreenHintEvent`) into
animated overlay widgets without modifying any domain resources. No violations.

#### Violations

None.
