# B10 - Lobby UI Leader status not updating

## Symptoms

- After re-joining, UI shows the old leader even though leadership has passed.

## Investigation

- Check how `LobbyInfo.leader_uuid` is replicated and how UI reacts to it.

## Findings

- Lobby UI determines "Leader" based on `player_idx == 0` in `LobbyInfo.players`.
- `LobbyInfo.leader_uuid` is also tracked but used more for authority checks than display in the player list.
- If a player rejoins and is assigned a different index but still sees themselves as leader (or others see them as
  leader), it might be due to stale data or incorrect index-based logic.
- The `prefix` (►) is based on `local_player.0 == Some(player.player_uuid)`, which is correct.
- The `leader_suffix` is based on `player_idx == 0`.
- The `name` for others is based on `idx == 0` in `update_display`.
- If a leader disconnects, `on_client_disconnected` updates `leader_uuid` but DOES NOT rearrange the `players` vector.
  However, `on_client_disconnected` for `ServerGamePhase::Lobby` (Hard remove) uses
  `lobby.players.retain(|p| p.player_uuid != uuid)`, which DOES shift indices.
- Action: Ensure "Leader" suffix in UI is consistently based on `lobby.leader_uuid` instead of index 0.
