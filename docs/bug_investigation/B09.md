# B09 - Truck interaction sounds should be shared

## Symptoms

- "End Mission" and "Craft Repellent" sounds are only heard by the player who clicks.

## Investigation

- Make these sounds positional and audible to all players near the truck.
- Use a broadcast message or spawn a replicated sound entity.

## Findings

- Added `PlayPositionalSoundBroadcast` message to `unreplicon-core`.
- Handled `PlayPositionalSoundBroadcast` in `unreplicon-plugin` to play positional audio on all clients.
- Updated `truckui_event_handle` in `untruck-plugin` to broadcast the "dingdingding" sound when "End Mission" or "Craft
  Repellent" is clicked on the authority.
- Sounds are now localized at the `VanEntryPoint`.

## Testing

They are not shared.

## REALITY:

crates/unaudiospatial-plugin/src/systems.rs:

```
pub fn spatial_audio_playback(
    mut sound_events: MessageReader<SoundEvent>,

```

SoundEvent is a regular message and we cannot send it across the network. That caused the failed mess described above
that was completely reverted.

This needs to be rethought, the initial approach didn't even work.

We need to make all in-mission sounds spatial by design.

We need to make all effects to be replicated over network by design.

But this needs more careful thought because there's already a lot of effort put on making the action to be replicated,
and that causes the sound to be called on each client locally - but when the action is not replicated,then the sound
would not be invoked.

We don't want to "replicate some sounds" - we do not want special cases. So we go back to designing this proper. We need
to think, is there a one-size fits all? Can we make all sounds replicated? can we make the action not cause the sound on
the client, and propagate always the sound in a parallel way?
