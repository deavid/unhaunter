# B13 - Gear grab/drop ownership disaster

## Symptoms
- Grabbing an item dropped by another player makes it disappear from ground but not appear in inventory.
- Desynchronized state between clients.

## Investigation
- Verify ownership transfer logic on the server.
- Ensure `LocallyOwned` is correctly managed and `Owner` change is handled.

## Findings
- Gear items were retaining `LocallyOwned` when dropped by a player.
- While this was intended for "distributed simulation", it caused issues when another player tried to grab the item, as `noop_remove` blocked component cleanup on the original owner's client.
- The proper flow according to coaching:
    1. Drop item -> Remove `LocallyOwned` (on dropper's client).
    2. Item on floor -> Retains `Owner(DropperId)` (Dropper still "simulates" but is no longer "possessor").
    3. Another player grabs item -> Server changes `Owner` to `NewOwnerId`.
    4. New owner's client adds `LocallyOwned` (via reconciliation loop).
- Action: Updated `queue_drop_request` to remove `LocallyOwned`. Updated `handle_request_grab` to correctly manage `Owner` and `LocallyOwned` transitions.
